# ADR-0013 — Identifier strategy: UUIDv7 entities, content hashes for integrity

- **Status:** Proposed
- **Date:** 2026-09-28
- **Origin:** BRT-02

## Context

IDs must be:

- globally unique, safe for distributed ingestion, and sortable where useful;
- independent of any blockchain;
- usable in APIs;
- free of PII leakage.

BRT-01 also needs content hashes for immutable objects.

## Decision

| Identifier kind | Form | Notes |
|---|---|---|
| **Entity ID** | **UUIDv7** (RFC 9562), generated by the application | Time-ordered, which keeps B-tree indexes efficient and cursor pagination natural. Generating ids in the app lets offline or ingestion paths create ids before commit. |
| **Version ID** | UUIDv7 (e.g. `result_version.id`) plus a monotonic `version_number` within its Result | The version is a separate entity from the logical Result |
| **Content hash** | `sha256:<hex>`, domain-separated (ADR-0014) | *Integrity* identity for immutable content. It is never used as the primary key of a mutable entity. Evidence blobs are keyed by hash. |
| **External source ID** | `ExternalIdentifier { namespace, value }` | Never used as a canonical id; the mapping is kept, and may be PII-adjacent (license numbers), so it is not public by default |
| **Blockchain reference** | `ExternalChainRef { network (CAIP-2), txHash, logIndex, address (CAIP-10), tokenId }` | An attribute of a domain object, never its identity |
| **Deterministic derived IDs** | e.g. `credential_id = H("credential-id", trophyClassId ‖ achievementId)`, `payout instruction hash` | Make duplicate issuance structurally impossible across systems |

**API rendering.** IDs appear as **TypeID** strings (type prefix + base32 UUIDv7, e.g. `ath_01j9…`, `rv_01j9…`) for readability and type safety. Hashed canonical content always uses the plain lowercase UUID string.

**Privacy note.** UUIDv7 embeds creation time at millisecond resolution. That is acceptable, because creation time is not PII and ids are not derived from personal data. Where even that is undesirable (e.g. a public reference to a minor's athlete record), an opaque random UUIDv4 **public alias** may be issued.

## Consequences

**Benefits:**

- Sortable ids.
- No coordination needed.
- Chain-independent.
- Uniform APIs.

**Costs:**

- 16-byte keys (fine).
- TypeID parsing is needed at the API edge.

## Alternatives considered

- **ULID:** equivalent properties, but UUIDv7 is now an IETF standard with native Postgres `uuid` storage.
- **DB-generated UUIDv4:** not sortable, and needs a round-trip.
- **Hashes as primary keys everywhere:** unsuitable for mutable entities.
- **Chain ids:** violate ADR-0006.
